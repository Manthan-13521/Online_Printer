## Security references and test criteria

- [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html): layered validation, size limits, randomized storage names, private storage, authorization, and content inspection. File signatures alone do not establish a safe or valid document. Use benign fixtures only; do not run PDF JavaScript or embedded attachments.
- [OWASP Web Security Testing Guide](https://owasp.org/projects/web-security-testing-guide): organize checks around authentication, authorization, sessions, input validation, business logic and client-side rendering. Passing isolated unit tests does not establish deployed protection.
- [Razorpay webhook validation](https://razorpay.com/docs/webhooks/validate-test/): verify HMAC-SHA256 over raw request bytes using the webhook secret. Deduplicate event IDs; tolerate repeated and reordered deliveries.
- [Razorpay integration](https://razorpay.com/docs/payments/server-integration/nodejs/integration-steps/): use server-owned order details when validating callback signatures; confirm captured payment state. Provider interactions in this audit are mocks only.
- [R2 presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/): signed method/key/header constraints and expiry need a real isolated R2 test; an in-memory object store cannot validate provider enforcement.

## Evidence labels

**MEASURED:** real local handler/repository execution and deterministic tests. **MODELED:** arithmetic with explicit workload assumptions. **ESTIMATED:** extrapolation with uncertain provider/runtime behavior. **NOT VERIFIED:** unavailable deployed analytics, browser/device results, provider signing enforcement or physical printer effects. A bounded local benchmark is never described as a Cloudflare CPU benchmark.
