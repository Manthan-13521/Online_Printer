## Changes in this pass

- `scripts/package-installer.mjs` requires native Windows compilation, validates actual PE inputs and approved Sumatra SHA-256, compiles Control Center and Inno Setup, and records a local build manifest. It cannot manufacture executables or a hosted release.
- SEA preparation now fails on errors, pins the postject version, and explicitly handles the copied Node signature before injection. See [Node's official SEA procedure](https://nodejs.org/download/release/latest-jod/docs/api/single-executable-applications.html). Native building needs Windows SDK signtool and later publisher signing; a Mac blob is not a Windows binary verification.
- Installer, Control Center restart and re-pair paths conservatively defer while relevant processes/journal exist. No print-state/claim/lease/retention/financial protocol redesign. A process check is not a transactional maintenance lock; supervised idle maintenance remains required.
- Support exports use an allowlist. Arbitrary host/display/printer names, raw provider errors, credentials, URLs and raw logs are omitted. Timing export intentionally omits step identifiers, so the technician correlates detailed timestamps locally rather than exporting customer identifiers. Existing local log sanitization is separate and is not claimed to catch every arbitrary name.
- The download UI requires technician-provided HTTPS URL, matching hash and version. `isLive` is configuration presence, not a network availability check; no hosted artifact was verified. Configure `VITE_WINDOWS_AGENT_DOWNLOAD_URL`, `VITE_WINDOWS_AGENT_SHA256`, `VITE_WINDOWS_AGENT_VERSION` only after release review.
- Developer model warning threshold is 65% for Workers requests, D1 reads and writes. No customer quota UI or new backend optimization was introduced.

## Owner journey and remaining gates

Intended owner flow: install reviewed Setup → connect from shop Admin → select/enable production printer → explicitly request one test page → operate from Admin/Control Center. No owner terminal, Node, Cloudflare dashboard or API URL entry. A technician builds/provisions and supplies the shop Admin bookmark. Control Center does not treat an API endpoint as an Admin site; its Admin shortcut currently instructs the owner to use the supplied bookmark. Direct shortcut provisioning remains PARTIAL.

Running-Agent restart/re-pair/update is deferred instead of forcibly killing the process. There is no owner graceful-stop workflow yet. Technician maintenance must pause intake, reconcile all work, then stop the idle Agent through a controlled maintenance procedure; never clear the journal to bypass a guard. Concurrent startup/installer races and long-running pairing completion need Windows acceptance. Do not use this candidate for unattended updates.

The shop Cloudflare deployment remains the control boundary. There is **no central licensing service or superadmin**. No paid add-on, multi-tenancy or inbound Agent server was introduced. Larger shops use the same software but need measured capacity and an approved infrastructure decision; Free-tier forever is not guaranteed by this model or by retained-history storage growth.
